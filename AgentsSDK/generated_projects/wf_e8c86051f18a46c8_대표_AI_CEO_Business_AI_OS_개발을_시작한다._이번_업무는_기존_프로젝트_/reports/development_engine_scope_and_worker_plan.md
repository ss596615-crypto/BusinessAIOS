# Development Engine 수정 범위 및 Worker 배정안

## 1. 수정 대상 요약
- 대표 지시 분류기
- 프로젝트/파일 검색기
- 함수·클래스 분석기
- 수정 대상 결정기
- Worker 배정기
- 자동 테스트 실행기
- 재수정 루프
- Git commit/push 단계
- 승인 대기 상태

## 2. 추천 Worker 역할
### Worker A: 레거시 코드분석 담당
- 기존 프로젝트 검색
- Python 파일 탐색
- 함수/클래스 의존관계 분석
- 수정 대상 후보 정리

### Worker B: 개발 구현 및 테스트 담당
- 실제 코드 수정
- 테스트 코드/자동 테스트 실행
- 실패 시 재수정 반영
- commit 준비

## 3. 추천 실행 흐름
1. 대표 지시 수신
2. 지시 유형 분류
3. 기존 코드 검색
4. GitHub 최신 상태 확인(권한 필요 시 대기)
5. 관련 파일 분석
6. 수정 범위 확정
7. Worker 배정
8. 코드 수정
9. 자동 테스트
10. 실패 시 반복
11. commit 생성
12. 대표 승인 대기
13. 승인 후 push

## 4. 구현 우선순위
1. Workflow 상태 모델 확장
2. Worker 작업 객체 표준화
3. 파일 검색/분석 함수 재사용
4. 테스트/재시도 루프 연결
5. Git 단계 분리

## 5. 제한사항
- 외부 GitHub 검색/푸시 권한 없음
- 실제 저장소 변경은 이 환경에서 수행 불가
- 현재는 설계/분석 문서 수준 완료
