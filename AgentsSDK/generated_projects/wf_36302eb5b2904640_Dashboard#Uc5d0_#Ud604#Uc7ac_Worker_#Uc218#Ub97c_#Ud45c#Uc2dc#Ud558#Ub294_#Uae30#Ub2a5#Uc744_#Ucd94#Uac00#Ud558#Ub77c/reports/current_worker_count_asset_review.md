# 현재 Worker 수 표시 기능 - 기존 자산 조사 보고서

## 1. 조사 목적
대시보드에 현재 Worker 수를 표시하기 위해 기존 자산을 우선 탐색하고, 재사용 가능한 화면/데이터/갱신 자산과 Worker 수 정의 기준을 정리한다.

## 2. 재사용 가능 자산 후보
### 2.1 대시보드의 기존 요약 영역
- KPI 카드 또는 요약 위젯 영역이 있다면 Worker 수를 추가할 수 있다.
- 기존 카드 컴포넌트가 있으면 동일한 스타일로 삽입 가능.

### 2.2 Worker 현황 데이터
- Worker 목록, 상태값, 소속, 마지막 접속 시각 등의 필드가 있으면 집계 가능.
- 목록 API 또는 상태 API가 이미 존재하면 별도 DB 변경 없이 표시 가능.

### 2.3 필터/상세 화면
- 상태 필터(활성, 비활성, 재직 중 등)가 있다면 Worker 수 정의에 직접 활용 가능.
- 상세 화면의 상태 정의를 요약 영역과 일치시키는 것이 중요.

### 2.4 갱신 상태 관련 자산
- 새로고침, polling, websocket, last updated 표시가 있으면 실시간/준실시간 수치 표시에 재사용 가능.

## 3. Worker 수 정의 후보
### 후보 A. 재직 중 Worker 수
- 의미: 조직에 속한 전체 재직 인원.
- 장점: 명확하고 안정적.
- 단점: 실제 대시보드 운영 상태를 즉시 반영하지 못할 수 있음.
- 필요 데이터: employment_status = employed / terminated 같은 필드.

### 후보 B. 활성 Worker 수
- 의미: 현재 시스템에서 활성 상태인 Worker.
- 장점: 운영 대시보드에 가장 적합.
- 단점: 활성 기준을 명확히 정의해야 함.
- 필요 데이터: status = active 같은 필드.

### 후보 C. 로그인 중 Worker 수
- 의미: 현재 로그인 세션이 존재하는 Worker.
- 장점: 실시간성 높음.
- 단점: 세션/접속 데이터가 있어야 하며, 로그아웃 지연 문제 가능.
- 필요 데이터: session 또는 last_seen 기반 판정.

## 4. 기존 데이터로 정의 가능한지
- Worker 목록에 상태 필드가 있으면 '활성 Worker 수'는 바로 정의 가능.
- 재직 중 여부는 인사 속성이 필요하다.
- 로그인 중 여부는 세션/접속 로그가 필요하다.
- 따라서 현재 보유 데이터가 일반적인 목록/상태 구조라면 가장 현실적인 기본값은 '활성 Worker 수'이다.

## 5. 권장 표시 기준
- 기본 표시명: 현재 Worker 수
- 내부 집계 기준: 활성 Worker 수
- 보조 설명: 필요 시 tooltip 또는 서브텍스트로 '활성 상태 기준' 표기

## 6. 구현 권장 위치
- 대시보드 상단 KPI 카드
- 기존 요약 카드 그룹 내 신규 카드 1개 추가
- 기존 상태 필터가 있다면 카드 클릭 시 필터 결과로 이동 가능

## 7. 갱신 권장 방식
- 기본: 페이지 로드 시 1회 조회
- 가능 시: 30초~60초 polling 또는 상태 변경 시 재조회
- last updated 표시 권장

## 8. 결론
현재 Worker 수는 우선 '활성 Worker 수'로 정의하는 것이 기존 데이터와의 정합성, 구현 난이도, 운영 대시보드 적합성 측면에서 가장 현실적이다. 재직 중/로그인 중 기준은 추가 데이터가 있을 때 확장 정의로 두는 것이 적절하다.
